Quake III: загрузчик моделей glTF (.glb) и модель игрока walker
================================================================

Состав
------
code/...                    изменения движка (см. ниже)
assets/zz-walker.pk3        модель игрока walker в формате .glb (нужен изменённый движок)
assets/zz-walker-md3.pk3    та же модель в MD3, для неизменённого quake3.exe
assets/baseq3/              содержимое zz-walker.pk3 в распакованном виде
                            (models/players/walker, scripts/walker.shader)

Готовый quake3.exe в репозиторий не кладётся: он собирается из code/ (см. ниже).

Лицензии: код — GPL v2, модель walker — CC BY-SA 4.0, данные игры Quake III не входят.
Подробно — в LICENSES.md.

Сборка на Windows 7 (MinGW)
---------------------------
Нужен 32-битный компилятор (i686): движок не рассчитан на 64 бита.
Подходят MinGW (mingw.org) или mingw-w64 в варианте i686.

    cd code
    mingw32-make -f Makefile.mingw

Результат: code\build-mingw\quake3.exe

В этой сборке нет JIT-компилятора QVM (vm_x86.c написан ассемблером MSVC и
Linux gcc), игровые модули (cgame, game, ui) исполняются интерпретатором.


Установка модели
----------------
1. Сделайте копию своего quake3.exe и положите рядом новый code\build-mingw\quake3.exe.
2. Скопируйте assets\zz-walker.pk3 в папку baseq3.
   zz-walker-md3.pk3 одновременно не кладите: если рядом есть .md3,
   движок берёт его, и загрузчик .glb не используется.
3. В игре: Setup -> Player, модель walker. Или в консоли:
       /model walker
       /team_model walker      (для командных режимов, красный и синий окрас)

Голосовых звуков у модели нет, движок берёт звуки модели по умолчанию.
Шаги: footsteps mech.


Переменные консоли
------------------
r_glbScale   множитель единиц glTF -> единицы Quake, по умолчанию 39.37 (метры -> дюймы).
             Значение из файла (asset.extras.q3_scale) важнее переменной.
             В модели walker записано q3_scale = 14.
r_glbDump 1  при загрузке .glb записать результат в glbdump/<путь>.md3
             (в папке записи игры). Так .glb можно перевести в MD3
             для неизменённого движка.
developer 1  загрузчик печатает число поверхностей, вершин, кадров и номера
             первых кадров каждой анимации.


Правила для своих .glb
----------------------
- Оси: glTF +Y вверх, +Z вперёд  ->  Quake +Z вверх, +X вперёд.
- Поверхность = материал. Имя поверхности (для .skin) = имя материала
  в нижнем регистре. Части с одним материалом объединяются, поверхность
  делится по лимиту движка: 999 вершин и 1999 треугольников.
- Имя шейдера: material.extras.q3_shader, если задано; иначе
  <папка модели>/<имя внешней картинки без расширения>; иначе
  <папка модели>/<имя материала>. Текстура ищется как .tga, затем .jpg.
  Картинки внутри .glb (PNG) не читаются.
- Анимации: каждая анимация glTF разбивается на кадры с частотой
  animation.extras.fps (по умолчанию 15) и добавляется в конец списка кадров
  в порядке массива animations. Без анимаций будет один кадр.
- Узлы с именем tag_* становятся тегами MD3 (не больше 16).
- Поддерживаются анимация узлов (перенос, поворот, масштаб; LINEAR, STEP,
  CUBICSPLINE) и скиннинг (JOINTS_0/WEIGHTS_0, до 4 костей на вершину).
- Не поддерживаются: morph targets, sparse-аксессоры, расширения
  из extensionsRequired (Draco, квантование и т.п.), внешние .bin.
- Порядок обхода треугольников переворачивается (в glTF лицевая сторона
  против часовой стрелки, в Quake по часовой).

Для модели игрока порядок анимаций такой:
  lower.glb: BOTH_DEATH1 .. BOTH_DEAD3, затем LEGS_WALKCR .. LEGS_TURN
  upper.glb: BOTH_DEATH1 .. BOTH_DEAD3, затем TORSO_GESTURE .. TORSO_STAND2
  head.glb:  без анимаций
Номера кадров для animation.cfg видны при developer 1.


Что проверено и что нет
-----------------------
Проверено:
- quake3.exe собирается MinGW из чистого клона с патчем, зависит только
  от системных DLL (kernel32, user32, gdi32, advapi32, msvcrt, ole32,
  winmm, wsock32);
- загрузчик скомпилирован отдельно с заглушками движка: три файла модели
  переводятся в MD3, части собраны по тегам так же, как это делает cgame,
  и отрисованы в разных кадрах;
- 900 повреждённых .glb (обрезка, мусор в JSON и в данных): падений,
  утечек и нарушений порядка освобождения временного хунка нет.

Не проверено: запуск самой игры. У меня нет Windows и файлов игры (pak0.pk3),
поэтому работа quake3.exe и вид модели в игре проверены только
по частям, перечисленным выше.
